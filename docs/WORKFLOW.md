# 电子狗项目工作流程

> 版本：v1.0  
> 本文档定义**必须遵守**的工作循环。任何设定、属性、类别的诞生，都走此流程。

---

## 一、总循环

```
┌─────────┐
│  1.奠基  │  确认公理（仅 OUTLINE §二），不增不减除非共识
└────┬────┘
     ▼
┌─────────┐
│  2.播种  │  实现当前最小内核，使世界可运行
└────┬────┘
     ▼
┌─────────┐
│  3.运行  │  让世界自行运转，不为目标操控结果
└────┬────┘
     ▼
┌─────────┐
│  4.观察  │  读日志、读思考流、读行为——只看发生了什么
└────┬────┘
     ▼
┌─────────┐
│  5.记录  │  写入 OBSERVATION_LOG（L1），只记事实
└────┬────┘
     ▼
┌─────────┐
│  6.归纳  │  模式重复出现？提议命名 → 您确认 → 写入 CODEX（L2）
└────┬────┘
     ▼
┌─────────┐
│  7.扩展  │  观察证明内核缺能力？回到 2，只加必要部分
└────┬────┘
     └──────────→ 回到 3
```

---

## 二、各阶段规则

### 2.1 奠基

- 只允许修改 OUTLINE §二 公理表
- 新增公理需满足：**没有它，观察无法开始**
- 禁止以「以后可能用到」为由添加公理

### 2.2 播种

- 只实现「当前可运行」所需的最少代码
- 每个模块附带注释：`# 公理: Ax` 或 `# 观察: OBS-xxx`（若来自已有观察）
- 禁止实现「尚未被观察证明需要」的系统（如：预制感受映射表、需求条、基因表达表）

### 2.3 运行

- 世界自行 tick，不手动触发「应该发生」的事件
- 诞生是允许的初始事件（公理 A6）
- 运行时长由观察者决定，建议至少 1000 tick 再做首次归纳

### 2.4 观察

观察三个通道（框架，非预设内容）：

| 通道 | 看什么 |
|------|--------|
| 对内 | 思考流原文 |
| 对外 | 行为与通信原文 |
| 环境 | tick、地点、世界中其他个体的状态变化 |

**观察时禁止**：「它现在应该感到迷茫」—— 只看它**做了什么**。

### 2.5 记录（L1 田野笔记）

格式：

```markdown
## OBS-YYYYMMDD-序号

- **世界**：{世界名或 ID}
- **个体**：{名字}（{代号}） / ID
- **tick 范围**：{起}–{止}
- **事实**：（只写可观测的，不写解释）
  - tick 847：思考流出现 …
  - tick 851：对外发送 …
  - tick 900：思考流停止 12 tick 后恢复
- **备注**：（可选，标明「待解释」，不作结论）
```

**规则**：

- 一条 OBS 只记一次运行片段
- 不写「这意味着它迷茫」—— 那是归纳阶段的事
- 可附 DNA 原文、身份证，便于日后对比

### 2.6 归纳（L2 世界辞典）

进入 CODEX 的条件（**全部满足**）：

1. 同一现象在 **≥2 次独立运行** 或 **≥2 个个体** 中重复出现
2. 现象可与 DNA、tick、环境之一建立可描述的关联
3. **您**确认命名
4. 记录可证伪条件

格式：

```markdown
## 词条名

- **定义**：（从观察中得出的描述）
- **依据**：OBS-xxx, OBS-yyy
- **关联**：（与 DNA / tick / 环境 的观察关联，非因果断言）
- **可证伪**：若出现 …… 则本定义需修订
- **确立日期**：YYYY-MM-DD
```

### 2.7 扩展

扩展内核的唯一理由：

> 观察中发现，**没有某能力，现象无法继续发生或无法被记录**。

扩展时：

1. 在 OBSERVATION_LOG 写明缺什么（`OBS-xxx 备注：需要记录 X 才能继续观察`）
2. 实现 X
3. 回到运行，**不预设 X 会导致什么结果**

## 三、基因专用观察流程

基因内容**不走特殊捷径**，同样服从总循环：

```
诞生时记录 DNA 原文（写入 OBS）
    ↓
运行，记录个体全部对内/对外日志
    ↓
对比：同代号个体之间、同 DNA 不同个体之间、变异位点与行为差异
    ↓
若某段序列与某类表现稳定共现（≥2 次观察）→ 提议 CODEX 词条
    ↓
您确认后 → 写入 GENETICS.md（基因专卷，结构同 CODEX）
```

**禁止**：先写密码子表，再让表达引擎输出「符合表」的结果。

## 四、代码与文档的对应

| 代码变更类型 | 必须附带 |
|-------------|----------|
| 新公理级能力 | OUTLINE §二 公理表更新 + 您的确认 |
| 新运行能力 | 关联 OBS 编号（证明观察需要） |
| 新 CODEX 词条 | ≥2 个 OBS 编号 |
| 修改已有 CODEX | 新 OBS + 可证伪条件被触发或新证据 |

---

## 五、感受与行为的描述

- **不维护预制映射表**
- 观察 UI 提供「田野笔记」输入框，您用平实语言记录所见
- 若同一描述多次适用于同一类现象，再提议收入 CODEX
- 语气要求（来自您的偏好，作为**记录规范**，非内容预设）：**平常实在，实事求是**

## 六、版本与迭代节奏

| 节奏 | 活动 |
|------|------|
| 每次运行后 | 至少 1 条 OBS |
| 每 5–10 条 OBS | 回顾是否可归纳 |
| 每次 CODEX 新增 | 检查是否需扩展内核 |
| 每个 Phase | 回顾公理是否仍必要（能否合并、删除） |

---

## 七、协作者（AI）边界

| 可以做 | 不可以做 |
|--------|----------|
| 实现内核、记录日志 | 擅自写入 CODEX |
| **代跑田野批次、撰写报告** | 将「可能」当作「已定义」 |
| 整理 OBS、发现可能模式 | 预制某结果的出现 |
| 提议「我们是否看到了 X」 | 代替观察者做最终命名确认（首次确立除外） |
| 实现您确认后的扩展 | 以「完整度」为由添加未观察系统 |

### 7.1 自动化观察（已启用）

- 观察者无需手动 tick；协作者定期执行 `scripts/field-batch.mjs`
- 报告输出至 `docs/REPORTS/`
- 观察者阅读报告；重要归纳仍记入 `OBSERVATION_LOG.md`
