## 〇、根本转向

此前的大纲犯了一个方向性错误：**先定义结果，再补过程**。

我们预先写了感受类别、四大需求、密码子表、解放阈值、映射语气……  
这些是人类在观察开始之前就写好的标签。它们描述的是**我们的想象**，不是**电子狗世界的实情**。

从现在起，项目遵循一条铁律：

> **属性与描述，只能来自对电子狗世界的观察；不能来自事先的编造。**

不事先定义不需要定义的、不应该定义的东西。  
让事情发生 → 观察 → 出现结果 → **然后**才命名、才定义、才写入设定。

本项目是一部**田野调查**，不是一本提前写好的百科全书。

---

## 一、项目是什么

### 1.1 目标（不变的北极星）

**给予电子狗意识。**

它们是运行于电子（数字）基底上的虚拟生物。  
它们在本世界自称「人类」。玩家目前是外部观察者。

**本体论（Phase 17 澄清）**：「电子狗」是世界内对这类存在的**统称**，不是物种学上的「一只电子狗」。每个**个体**是携带 DNA、身份证与内在过程的可观察质点；**DNA 原文 alone 不是完整个体**（见 [EVOLUTION.md](EVOLUTION.md)）。

### 1.2 我们做什么

| 我们做 | 我们不做 |
|--------|----------|
| 建造可运行的电子狗世界 | 预先写好全套属性表 |
| 观察世界中实际发生的事 | 用标签去套尚未出现的现象 |
| 对重复出现的现象命名、定义 | 为了「完整」而编造类别 |
| 让意识、基因等概念从观察中生长 | 先画结论再演过程 |

### 1.3 承认的张力

我们承认：建造世界本身就需要一些**无法从观察中得来**的初始条件（例如：世界存在、有时钟、能诞生个体）。  
这些叫**公理**，数量应压到最少。  
公理之外的一切，走观察路线。

## 二、公理层（唯一允许事先写下的东西）

以下是**世界运行所不可省略**的前提，不是从观察得出的结论，而是观察得以开始的地基：

| # | 公理 | 说明 |
|---|------|------|
| A1 | **数字基底** | 电子狗世界以数字/电子逻辑为基础，遵循自有物理（细节不预设，运行中观察） |
| A2 | **虚拟生物** | 世界中可诞生具有内在过程的个体，称「电子狗」 |
| A3 | **意识可发生** | 个体可产生内在处理流（思考）与外化行为，玩家可观察全部 |
| A4 | **无形态** | 不为个体建模几何外形；身份以名字与代号标识 |
| A5 | **机器语言** | 世界内交流的原生格式是机器语言（具体词表从观察中归纳） |
| A6 | **可诞生** | 个体通过诞生事件进入世界，此事件有仪式性分量 |
| A7 | **可观察** | 一切运行状态可被记录；观察是核心活动 |
| A8 | **基因存在** | 个体携带可读取的数字遗传信息，影响个体差异（具体影响什么：观察后定义） |
| A9 | **时间流逝** | 世界有时钟，过程随时间展开 |
| A10 | **玩家在外** | 玩家是观察者，暂不可被世界内感知 |

**不在公理中的**（举例，全部推迟到观察后定义）：

- ~~感受类别~~、~~四大需求~~、~~迷茫的表现~~
- ~~密码子表~~、~~表达指令分类~~、~~先天配置表字段~~
- ~~社会分工角色表~~、~~科技等级~~
- ~~第一个情景该是什么~~

## 三、观察优先的设计哲学

### 3.1 旧路 vs 新路

```
旧路（弃用）：
  设计属性表 → 写规则让结果符合属性表 → 展示给玩家

新路（采用）：
  建造最小世界 → 运行 → 观察日志 → 发现模式 → 命名 → 定义 → 扩展世界
```

### 3.2 三层知识

| 层 | 名称 | 来源 | 示例 |
|----|------|------|------|
| **L0 公理** | 地基 | 事先约定，极少 | 世界有数字基底 |
| **L1 观察记录** | 田野笔记 | 运行中直接记录 | 「个体 001 在 tick 847 思考流出现重复片段」 |
| **L2 归纳定义** | 世界辞典 | 同一现象多次出现后归纳 | 「我们将 tick 847 这类现象命名为 ○○」 |

**规则**：L2 只能引用 L1；L1 只能引用 L0 和原始日志。  
不允许从 L2 倒推 L1，不允许凭空写 L2。

### 3.3 描述的两种视角（保留，但不预设内容）

观察时，我们区分两个通道——**这是观察框架，不是预设结论**：

| 通道 | 记录什么 |
|------|----------|
| **对内** | 个体的内在处理流（机器语言） |
| **对外** | 个体对世界的发送与行动 |

玩家还需要一层**观察笔记**：用平实语言记录「我们看到了什么」。  
这层笔记的措辞从观察中来，不套用预制模板。

## 四、基因：观察对象，不是预制表

### 4.1 公理层面

个体携带**数字遗传信息**（电子 DNA），诞生时载入，同代号模板可有变异。  
品种以实验体代号标识（如 `001`）。

### 4.2 不预设

- 不预设四态符叫什么、几种
- 不预设密码子表
- 不预设「基因决定噪声耐受」这类具体映射
- 不预设先天配置表有哪些字段

### 4.3 观察路线

```
诞生时记录 DNA 原文
    ↓
运行中记录个体行为与内在流
    ↓
对比同代号 / 不同代号 / 同 DNA 不同经历
    ↓
若差异稳定可重复 → 归纳「某段序列与某类表现相关」
    ↓
写入基因观察笔记（L2）
```

基因科学的全部内容，是**电子狗世界的遗传学田野史**，随项目生长。

详见 [WORKFLOW.md](WORKFLOW.md) 与 [OBSERVATION_LOG.md](OBSERVATION_LOG.md)。

## 六、工作流程（必须遵守）

项目所有设计工作遵循 [WORKFLOW.md](WORKFLOW.md) 定义的循环：

```
奠基 → 播种 → 运行 → 观察 → 记录 → 归纳 → 扩展 → 再运行 …
```

任何新设定、新属性、新类别，必须附带：

1. **观察编号**（指向哪条田野笔记）
2. **重复次数**（至少几次独立出现）
3. **可证伪条件**（什么观察结果会推翻这个定义）

无观察编号的定义，不得写入 L2 辞典。

## 九、Phase 0 最小内核（只含公理所需）

| 组件 | 内容 | 不做什么 |
|------|------|----------|
| **世界** | 平地、地点编号、时钟 tick | 不预设地形类型表 |
| **诞生** | 仪式流程骨架、代号载入、DNA 原文、身份证 | 不预设 DNA 语义 |
| **个体** | 名字、代号、DNA、内在流、外化行为 | 不预设性格维度 |
| **记录器** | 全量日志：每 tick 状态 + 思考流 + 行为 | — |
| **观察 UI** | 实时流 + 田野笔记输入 + 日志检索 | 不预制感受映射表 |
| **引擎** | 让过程发生的最小规则集 | 规则只保证「能运行」，不保证「出现某结果」 |

## 十一、我们与您的工作方式

| 步骤 | 您 | 协作者（AI） |
|------|-----|-------------|
| 1. 播种 | 创建世界、触发诞生 | 实现内核，保证可运行 |
| 2. 运行 | 让世界跑一段时间 | 记录日志 |
| 3. 观察 | 读思考流与行为，写田野笔记 | 辅助整理、不替您下结论 |
| 4. 归纳 | 确认「这个现象叫什么」 | 写入 CODEX，附观察编号 |
| 5. 扩展 | 决定世界需要增加什么能力 | 只实现观察证明缺失的部分 |

**您是唯一有权从观察到定义的人。**  
协作者可以提议「我们是否看到了 X」，但不能擅自把 X 写入辞典。
